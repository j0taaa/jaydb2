# V6 functional integration design — 2026-10-29

This is a first functional extension, not a proof of general frontend preservation or full generality. The original Bend/Lean/kernel rules and all V1–V5 artifacts are unchanged. Active contract3 is ROOT's separately authorized migration. SourceStringmax, mutual generated live groups and unimplemented typed forms remain explicit operational/representation limitations; failure to translate is never a theorem that the source proposition is false.

## Common boundary

Both routes use the same source snapshots, Book, imports/capability audits, original initial and final primary checker, prospective physical closure and postclosure audit. R4 only reuses cross-key EQ candidates whose v and e are complete; exact provisional reservations retain the original recursion discipline. Closure discovers erased calls without replacing source types by physical heads; every live call resolves to the actual compiler instance. It independently re-elaborates all physical instances/aliases and reached ordinary/Base source declarations. Their source claims compare actual .e with independently elaborated source, in physical mode. Existing .e is never substituted as the expected source. No Book definition may appear after the final check.

The old complete physical payload remains available. Dispatch inspects typed proof headers and the body's observed typing BEFORE a kernel verdict. It never catches BENDTT_CHECK or a failed guard to try a different payload. The structural branch canonicalizes affected erased indices to one parametric logical body preserving equations and commuting with ordinary substitution. It does not specialize ordinary numbers or invent inhabitants. Every raw physical root remains live and every required physical source_link remains in that branch's payload. Changed proof headers and every relevant original target receive exact evidence obligations, even if the structural header already happens to match and needs no promotion.

## Evidence and execution

Relations are generated compositionally from actual source types and actual checked bodies: Sigma packets for family fields, one live evaluator for functions, exact physical/logical indices erased, and existing J for endpoint links. Strong equality representations retain exact evidence and coherence; no funext, proof irrelevance, K or new axiom. ProofBody supplies evidence at the original target AND Eq of that exact evidence value to the original logical source-body application, plus an evidence-dependent transport. Actual closed inputs build their relations from source constructions. Abstract R_h premises in generic helpers never certify a closed application without a constructed R_h. Universal proof inputs use reflection only for structurally justified domains; unsupported opaque domains fail technically.

Operational evaluators are generated only for transported proof roots and their dependencies, plus executed roots that actually change representation. A root may omit transport only if its raw declaration exists, its physical/logical head is literally identical, the transitive source dependency graph marks it unaffected, and its observed/original header is identical. The graph includes T/v/e and datatype fields, so changing a dependency to a template prevents this identity cut. All physical source links remain mandatory even for an identity root: a new negative changes Base while main's head remains unchanged and must fail its source_link. All generated live declarations are ordered by live dependencies; the original affine/descent judgment still checks them. A nontrivial generated mutual live group is currently unsupported, never made opaque or axiomatized.
