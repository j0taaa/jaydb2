## One logical judgment and a separate operational relation

The intended logical judgment is a single parametric interpretation of a checked source term. Its template parameters remain symbolic binders, its defining equations come from the actual checked generic `.e`, and substitution acts on that interpretation. A physical specialization does not create a second logical function with an unrelated recursive head. In particular, substituting `p := 3` in an ordinary theorem must produce the same logical index as a direct source occurrence `f(3,n)`, including when evaluation is blocked on `n`.

Canonicalizing only erased indices already fixes this substitution problem. It does not by itself establish an operational link: an actual value produced by physical `f~0` can index an ordinary function's result, and that ordinary function can consume the value. A physical function may also be passed partially applied, capture a linear Token, or be returned and applied later. Replacing every live physical reference by the logical family would remove the exact physical behavior being checked. Keeping two heads and asking for an equality of whole functions would instead require extensionality unavailable in the original kernel. Neither step is justified.

I therefore reject the proposed simplification **if it means keeping only parametric logical typing plus the existing source links, with no checked operational relation at the value boundary**. The links compare actual and independently elaborated physical bodies. They are not a theorem that arbitrary physical and logical function heads are interchangeable. Treating them as that theorem would silently assume frontend preservation. No gate has been removed on that basis.

The prototype instead retains the one parametric logical judgment and adds an operational representation, not a second specialization of the theorem. For a scalar expression the representation computes one value `y` and returns original-kernel evidence `y = physical-expression` and `y = logical-expression`. An ordinary proof consumes `y` once; equality elimination transports its dependent result to the single logical index. The physical expression appears in the checked evidence. No model witness or axiom supplies either equality.

For functions, the proposed representation has two erased indices (the exact physical function and the one logical function) and one live evaluator. The evaluator receives arguments and returns a single value plus its two pointwise links. It does not assert equality between the functions. An ordinary callee with such an argument can retain its original logical conclusion while a derived implementation receives the checked evaluator. The original callee remains an independently checked live root. Recursive forwarding passes the same representation rather than specializing ordinary numerical arguments.

This is an implementation design, not yet a proven general translation. The current function prototype is being checked against the original kernel rules before any production rebuild. The translator must eventually handle dependent codomains, function-valued results, and abstract/constructor-contained function types uniformly; syntactic recognition of a few Nat function signatures is not a general solution.

## Position and ownership discipline

* Original `.T` and `.v` retain their source spelling. Closure discovers all needed physical instances there; it does not force their erased type syntax to use physical heads. The actual existing `.e` is resolved to the physical declarations consumed by the compiler.
* Independent expected source trees are obtained by original elaboration, then resolved physically. Existing actual `.e` is never replaced by this expected tree.
* Every real physical root, including aliases and Base instances, retains a live check and mandatory physical source link. That mode does not canonicalize actual versus expected physical dependencies. A direct body change from Nat1 to Nat2, a changed inner/outer dependency, or a changed alias must still fail its own kernel guard.
* The final original primary pass, final capability audit and both final checkers run only after closure reaches a stable complete graph. The certificate and C emission use that same sealed Book, and no Book definition may be introduced after final checking.
* Generated operational evaluators and conditional callee implementations are kernel declarations only. They do not add physical Book instances or replace a compiled body. Each generated proof is checked under existing quantities, elimination and descent rules.

## Coverage obligations for the representation

Application partially supplies a function representation and captures its actual arguments once in the remaining evaluator. Returning a function returns a representation at the function type rather than an equality of function heads. A captured Type/Token value may occur in erased logical indices, but has exactly one live owner in the evaluator closure; duplicating it to evaluate the physical and logical sides is invalid. Reusable Data retains its existing quantity.

Dependent domains require the evaluator's actual argument to carry its own logical link and require explicit existing equality elimination wherever the codomain mentions that argument. Passing a represented value through an ordinary function must preserve this link under substitution, rather than derive a fresh physical specialization from an open ordinary value. Constructor fields and abstract type parameters need the corresponding typed representation as well; that obligation is not discharged merely because an outer result has a Nat carrier.

The scalar prototype currently passes twelve additional cases including consumed recursive values, two separate linear Tokens, partial functions and recursively forwarded function values. A higher-order function that captures Token and is consumed by an ordinary recursive theorem exposed the remaining boundary. A passing isolated scalar set is not evidence that all the obligations above are complete.

It is separate from the already tested huge-deadline Node API domain and is deferred while R4/R5/Token are resolved.

## Structural representation chosen for recursive data

The Church experiment established a pointwise link through a nonrecursive Token field, but its function-valued eliminator does not expose a recursive child as a constructor subfield to the original descent checker. It is not the final recursive representation.

A Sigma record preserves that information. Its runtime layout contains a constructor tag and a field packet. A represented field carries erased physical/logical indices and its one live field representation. A recursive field contains the child's representation as a direct runtime subfield. Two live Data equality proofs link the reconstructed physical/logical constructors to the two outer indices. These are checked endpoint proofs, not equality between unrelated functions. Actual Fn fields remain linked by their one evaluator and pointwise evidence. Matching the record and using existing J transports the source goal to its logical constructor.

`/tmp/jaydb2-v6-records-work/list-rel.bendtt` is a manually generated UNIVERSAL feasibility lemma for this layout: an arbitrary represented list of arbitrary related functions is consumed by a structurally recursive evaluator. It computes each function result once, recurses on the represented tail, sums the results, and returns both exact physical and logical total-function links. The original kernel accepts its structural descent. The existing kernel's pattern tracking requires annotations after the field split, so the recursive child's provenance remains visible; the convoys carry dependent endpoint evidence across that split. No change to descent or to kernel conversion is used.

`check.json` records acceptance by both kernels (the budgeted kernel starts at fuel 1 and reaches a definitive answer after 10 attempts at 512) and two causal refusals by both: changing the exact physical total body to constant zero, and replacing the logical endpoint link with the physical one. These are isolated kernel artifacts, not a completed generic adapter or a new independent review. The generator still needs the same typed construction for polymorphic families, higher-order dependent domains, abstract types and result representations before production can be frozen.

## Compositional research generator after the interruption

Physical/logical function heads are never equated.

The term-level bridge test connects the generated recursive fold to the already checked physical `f~0` capturing Token.
