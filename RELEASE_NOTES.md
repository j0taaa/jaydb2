# English-language migration — unreleased

Current `main` uses English-only documentation, CLI options, protocol names,
Bend symbols, and module paths. Request records use `arguments`, `code`,
`credential`, and `proof`; responses use `status` and `value`; limits use
`message`, `state`, and `response`; user records use `credential`, `id`, and
`kind`. Existing clients and application sources must migrate; there are no
legacy aliases. Binary tags and framing are unchanged, but renamed fields and
status values are an API break. The v0.1.0 notes below describe that historical
release; the English migration does not retroactively rerun its checks.

The migrated tree was validated locally: the contract and both pure aggregates
passed the two official checking modes, and all six false-proof controls were
rejected. The 26 admission/runtime/host/integration tests and three web-demo
tests passed. The task application's 17-call session and three proof-negative
controls also passed with the English interface. The credential demo ran on
the real server. No GitHub Actions workflow was added or used.

# 0.1.0 — experimental release

A serial RAM database over stdin/stdout: Rust host, Node admission, and ordinary
executables generated by official Bend 2.0.39. Three logical size limits; no
physical accounting or custom per-request deadline.

## Usable path

[INSTALL.md](INSTALL.md) covers local installation, tools, downloading the
pinned BendTT, and running `make demo`. The credential application uses real
identity-based read/write laws, a universal proof, and publication in the real
server. The session demonstrates success, authentication, and refusal rollback.

## Review and simplification in this release

Two subagents independently reviewed the Rust/C bridge and Node
admission/compilation, without editing the candidate or running new suites.
They found no concrete defect within the examined scopes. Review confirmed
the correspondence between sources/metadata, the private snapshot, steps,
the reaped process, the complete proposal, store, and delivery described in
[SERVICE_CONTRACT.md](proof/SERVICE_CONTRACT.md). This is review evidence,
not a mechanized proof of the integration.

A third audit identified four local simplifications: unused verifier and loop
walker parameters, duplicate diagnostic parsing, and a repeated runtime
assertion. Tests of distinct boundaries were retained. No second
implementation or parallel suite was created.

## Guarantees and limitations

`ContractService.contract_of_service` composes exactly the eight laws under the
explicit tool and integration contracts. Rust/Node/C, Clang, the operating
system, and semantic preservation by official tools belong to the trusted
base. Review and tests do not remove these assumptions.

The instance can be lost with its process. There is no persistence, network
listener, or transaction concurrency. Observed official Nat/Array limitations
remain [documented](native/SIMPLE_RUNTIME.md); JayDB does not modify Bend to
work around them. Compilation and proofs can consume substantial resources or
time; availability is not guaranteed by custom quotas.
