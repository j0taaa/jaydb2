FINDINGS

1. Volatile latency variability is explained by CPU frequency regimes, not an observed fixed transport wait. In one unchanged 100-row native artifact, process CPU medians were 2.379 ms at >4 GHz (n=5) and 13.476 ms below 900 MHz (n=4). Corresponding wall times were 2.380 and 13.508 ms. Minor faults stayed near 324; median major faults and voluntary context switches were zero. Input writes of 6431 and 8958 bytes completed in about 12-13 microseconds in the trace. The powersave/balance_performance policy was left unchanged. perf was unavailable because perf_event_paranoid=4.

2. Every successful Commit previously created .snapshot.tmp, wrote a full image, fsynced the file, renamed it over snapshot, and fsynced the database directory. The image is 16-byte magic, 64-byte environment identity, four u64 fields (message/state/response limits and state length), canonical state, and 32-byte SHA-256: 144 bytes plus state. A 10-row point state is 898 bytes, so a read rewrote 1042 bytes. The trace measured roughly 10.6 ms for the two fsyncs; E2 read publication had an 11.714 ms median. Separate last-response, request-sequence and prepared-registry records are not in the image. Optional administrator timing/stderr logs still write, but are not request-synchronized database images.

SAFE CHANGE

A Commit with byte-identical canonical state reuses the current durable image; the exact new root/response pair is still published in RAM. Environment and limits are immutable, and all other image fields are deterministic, so this condition means the complete persisted image is byte-identical. Every changed state still completes file fsync, rename and directory fsync before RAM publication and reply. Application idempotency receipts are ordinary state rows, so new receipts still take the full durable path.

Recovery now fsyncs the validated authoritative file and directory once before serving. This is necessary because the previous process may have died after rename but before directory synchronization. It establishes the durable-current-state invariant before any equal-state shortcut. The root/last-response pair and allocated-handle history still obey T3 in RAM; they were never persisted as separate fields. proof/README.md clarifies this scope without changing a T3 duty, Bend semantics, wire bytes or theorem statements.

MEASUREMENT LIMITS

All headline samples use the original harness boundaries, official Bend 2.0.39/BendTT, literal emitted C, Clang 19 and one native worker thread. No CPU governor or affinity was forced. Quartiles below are inclusive Q1 and Q3, with no outlier removal. Frequency changes confound before/after differences beyond eliminated image IO: do not attribute the full 28.398-to-3.092 ms read reduction solely to fsync. The native observer and syscall-traced measurements are separate diagnostics, not headline samples.

Registration n=3 is independent one-time preparation. Ordinary operation n=10, prepared/comparison n=300 and scaling n=50 exclude one warmup. Active throughput has n=10 blocks of 30 calls, excluding maintenance/gaps. Closed-loop throughput is one full batch observation, including voucher retirement. Verification timings are single command wall times (n=1), so quartiles are undefined. SQL/JayDB2 timing boundaries differ as documented in paper/README.md; SQLite is an unconstrained baseline.
